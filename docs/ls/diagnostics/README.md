# 標準モデルの歩行不足を切り分ける診断

`probe_policy.py`は保存済みチェックポイントを読み込み、通常の決定論的推論と、学習時の行動分布からサンプリングする推論を各30秒以内で比較する診断専用スクリプトです。学習、optimizer更新、重み保存、最終評価の置換は行いません。

```bash
python3 docs/diagnostics/probe_policy.py
```

デフォルトは`outputs/baseline/final.pt`を読み、`outputs/baseline_policy_probe/`へ記録します。既存出力には上書きしません。再実行時は`--output`で別の保存先を指定します。

- 元の評価と同じ変換・指令列、seed 100を使う。各モードで環境を作り直し、初期状態も記録する。
- 毎ステップ、指定指令と実際のcommand buffer、policyに渡すactor観測の指令領域を照合。不一致なら内容を保存して停止する。
- 同じセンサー観測で指令だけを変えたとき、出力関節指令がどれほど変わるかを記録する。
- 正規化器がevalモードで、診断中に状態を更新しないことを確認する。
- 区間ごとの実速度、行動RMS、終了理由と、Brevにインストール済みの関連クラスのソースを保存する。
- 確率的推論の結果が良くても、元の決定論的評価の成績を置き換えない。探索ノイズへの依存を調べるための補助実験として扱う。

`docs/`は既存の学習ソースハッシュの対象外です。この診断の追加では学習コード・設定・テストのハッシュは変わりません。診断自体のSHAはprobe.jsonに保存します。ローカルでは構文・helpを確認済み。GPUでの実行はBrevで必要です。

## 目標到達後の停止を調べる追加実験

`hybrid_goal.py`は、移動に標準model_1000（1001更新）、立位維持に同じ学習のfinal（4000更新）を使います。両モデルの機体・観測・行動・設定・依存・学習ソースの互換性を検査し、各モデル自身の正規化器を保持します。

```bash
python3 docs/diagnostics/hybrid_goal.py
```

- 出力は`outputs/hybrid_goal_pilot/`。既存出力を上書きしない。
- 目標から0.12 m以内で立位モデルに切り替え、0.18 mより外へ出た場合は移動モデルに戻す。半径差は切り替えの繰り返しを抑えるため。
- 成功基準は元と同じ：目標半径0.15 m以内、速度0.05 m/s以下、旋回速度0.15 rad/s以下を2秒維持。制限時間30秒。停止モデルへの切り替えだけでは成功にしない。
- 物理状態や関節角を直接書き換えず、関節指令を出すポリシーのみを切り替える。新たな学習や公式の既存重みは使わない。出力の補間は行わず、切り替え安定性を実測する。
- 初回は既に単一モデルで失敗を観測したseed 300〜302を使う開発実験。成功しても独立した最終検証と呼ばず、方針を固定してから未使用seedで追加検証する。
- 元の単一モデル評価・標準と低速の比較はそのまま保持し、別の追加実験としてレポートに記載する。実験スクリプトのSHAと両モデルのSHAを記録する。

開発3試行は3/3成功、成功まで平均9.31秒、最終目標誤差平均12.0 cmでした。CSVで最後の2秒間の距離・速度・旋回速度が全基準を満たすことを確認しています。記録は`outputs/review/hybrid_goal_pilot/`に保存しました。

続いて制御・モデル・成功基準を固定したまま、未使用seed 400〜409の10試行を行います。

```bash
python3 docs/diagnostics/hybrid_goal.py --validation
```

出力先は`outputs/hybrid_goal_validation/`、評価区分は`held_out_validation`です。開発結果と混ぜずに集計します。2026-10-31に取得した初回検証は10/10成功、転倒0、停止完了まで平均10.476秒、最終目標誤差平均0.121422 mでした。全10試行の最後の2秒間が距離・速度・旋回速度の基準内であることをCSVから確認しました。記録と検証時のスクリプトは`outputs/review/hybrid_goal_validation/`に保存しています。同じseedを再実行しても新たな未使用seedの検証にはなりません。

## 目標へ近づく速度を上げる開発実験

```bash
python3 docs/diagnostics/hybrid_goal.py --fast-approach
```

速度指令を`min(0.4, 0.8 × 距離)`から`min(0.4, 1.2 × 距離)`へ変更します。目標の約50 cm手前から始めていた減速を約33 cm手前からにし、近づく区間の速度を上げられるか調べます。前進指令の上限0.4 m/sは採用モデルの学習範囲です。実際の歩行速度が指令値に一致する保証はありません。

- 変更する制御パラメーターは`distance_gain`のみ。移動・停止モデル、旋回制御、切り替え半径、成功基準、物理ステップ、録画速度は同じ。追加学習は行わない。
- seed 300〜302を使用し、出力先は`outputs/hybrid_goal_fast_pilot/`、評価区分は`development_speed_comparison`。元の開発3試行と初期状態・実速度・停止完了時間・成功率・最終距離を比較する。
- `--validation`との同時指定は不可。既に確認した元の方式の10/10成功を、速度変更後の性能として扱わない。
- 2026-10-31に開発結果を確認。共通3試行で前進指令中の平均実前後速度は0.138552→0.187629 m/s、停止完了までの時間は9.313→8.013秒（約14%短縮）。成功は両方3/3で、速度変更後も最後の2秒間の停止基準を全試行で満たした。両モデル・初期状態・seed・変更項目を照合済み。実測記録と比較は`outputs/review/hybrid_goal_fast_pilot/`に保存。

開発結果の確認後、速度変更版を固定して未使用seed 500〜509で検証します。

```bash
python3 docs/diagnostics/hybrid_goal.py --fast-validation
```

出力先は`outputs/hybrid_goal_fast_validation/`、評価区分は`held_out_speed_validation`です。速度変更版の開発時から変えるのはseed・記録区分・出力先のみです。他のモードとは同時指定できません。2026-10-31に取得した初回の結果は10/10成功・転倒0、停止完了まで平均11.804秒、最終目標誤差平均0.116057 mでした。全試行で最後の2秒間の停止基準をCSVから確認しました。元の方式のseed 400〜409とは初期条件が異なるため、両者の平均時間の差を同条件の速度改善として計算しません。速度の比較は共通の開発seed 300〜302で報告し、未使用seedの評価は成功率・停止維持の追加検証として扱います。確認用動画の生成・再生手順は`docs/video/README.md`にあります。

GPU不要の切り替え・互換性テスト：

```bash
python3 -m unittest discover -s docs/diagnostics -p 'test_*.py' -v
```
